## Shared conventions for every program

* **Golden record** (one JSON object per line, same shape as the Rhino corpus): `id`, `build` (program version string, or service date for
  cloud programs), `tolerance` (the program's own document or model tolerance, recorded as data), `ok`, `error` (exception type name only),
  `out` (numbers, counts, flags only), `ms`. Strings longer than 200 characters are rejected. No geometry dumps.
* **Case ids** `<PROG>-<FAMILY>-<nnnn>` generated by a deterministic `gen_cases.py` per program from closed forms and parameter sweeps we
  write; never from the program's samples, templates or help examples.
* **Runner contract**: reads `D8_CASES`, `D8_OUT`, optional `D8_LIMIT`, `D8_ONLY`; first run is a 5-case smoke, then the full corpus twice;
  records that differ between the two passes are quarantined (G5), not averaged.
* **Tolerance classes** are fixed in each program's compare script and changed only by the reviewer:
  * exact: counts, flags, topology numbers, enumerated results
  * pure double math: relative 1e-9
  * kernel geometry (area, volume, length): relative 1e-4 (as in rhino/compare.py) unless the program documents a coarser tolerance
  * single-precision engines (Blender): relative 1e-5 plus absolute 1e-5 times model scale
  * stochastic or time-dependent output (renders, physics, cloud analyses): compare statistics (mean, variance) inside the program's own
    run-to-run spread, which the golden record stores
* **Edge-case sweeps**: every operation family includes tangent, coincident, near-tangent, degenerate and large-scale cases, because
  refusals and failure types are data (the Rhino corpus produced 24 such refusals out of 200).
* **Contamination rules**: no vendor strings, assets, sample files, help text, screenshots or identifiers that are not public API; option names
  may be recorded as identifiers only.
