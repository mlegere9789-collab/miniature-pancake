Scope: plan sections 4 and 7.4, parity matrix (report chapter 8). Every finding below was fixed in the generator; no row was edited by hand. Rows are regenerated by `python3 parity/tools/gen_blender_register.py`; `--check` proves the committed output equals a fresh run.

## 1. Target tier

Rule (now in the generator, comment block `Targets`). Best is allowed only for the user-facing tools of the matrix rows where Blender is class-leading: polygon/mesh editing, sculpting, path tracing, animation and rigging, physics simulation, compositing and video, scripting API. Inside a Best module, plain selection primitives (select all, box, circle, lasso, more, less, linked, click), view/zoom/pan, frame jumps, cursor placement and preset-add helpers stay Strong: they are commodity behavior, the class-leading outcome is the tool. The matrix rows for licence, open data and standards, extension ecosystem size and roadmap transparency are platform rows without a bpy operator, so import/export, extensions and asset operators stay Strong; those four rows are not in this register yet (open item).

Defects found in the old assignment:

- `text` (43 rows) and `text_editor` (1): the Text editor area is a code editor, not the bpy scripting API. Now Strong. `script.execute_preset` Strong, `script.python_file_run` and `script.reload` stay Best.
- `marker` (11): timeline markers are animation infrastructure, not a matrix capability. Now Strong.
- `render` (16): only `render.render` is path tracing; presets, texture cache, view show/cancel, OpenGL preview (real-time is rated Strong in the matrix) are Strong. `cycles.use_shading_nodes` (legacy node switch) Strong.
- `*preset_add` helpers in cloth, fluid, particle, clip, camera and others, and view/select chrome in every Best module (62 rows): Strong.
- Missing Best: `sequencer` (99 of 116), `clip` (65 of 91), `mask` (29 of 40), compositor operators in `scene` and `node` (27), physics and rigging operators in `object` (31: particle, force fields, quick smoke/liquid/explode, ocean, constraints, armature add, shape keys, deformer binds, tracks), sculpt-mask and hide/show gestures in `paint` (13), the four mesh extrude operators in `view3d`, animation transport in `screen` (9, extracted from the group row), `console.execute` and `console.autocomplete` (2).
- Appendix B: 16 modifiers are now Best (Cloth, Collision, Dynamic Paint, Explode, Fluid, Ocean, Particle Instance, Particle System, Soft Body, Surface; Armature, Mesh Deform, Surface Deform, Laplacian Deform, Corrective Smooth, plus the alias row of Armature). Compositor nodes (90) and constraints (29) were already Best and stay. Geometry nodes, shader nodes, GP effects and editor containers stay Strong (matrix: Strong via Geometry Nodes; editors are containers).
- Judgment calls, stated so the owner can overrule them: clip tracking and masks are treated as compositing/video (Blender has no incumbent peer there); shape keys and deformer binds count as rigging; GN simulation zones and the XPBD node stay Strong because the matrix rates visual programming Strong; Grease Pencil drawing is Strong (no matrix row). If the owner removes clip and mask from Best, Best falls by 94 rows.

## 3. Statement quality

Before: every operator row read `User can \"<UI label>\" in <area> with the same outcome as Blender 5.3 bpy.ops.x.y`, every node, modifier and constraint row read `User can use the \"<label>\" ... with the same results as Blender 5.3`. That repeats the label, says nothing a test can check, and 50 labels collide inside one module (for example mesh `Add Cube` twice) so statements were told apart only by the operator path.

After: each statement states what the user can observe and verify. Operators get a verb class (select, view, create, remove, copy, paste, place, toggle, set, process, load, store, run) from the UI label's first word, falling back to the operator name, and a class template says what changes, what must not change and that one undo step restores it. The label stays quoted so rows remain searchable. Colliding labels get a `Variant: operator module.name` suffix. Appendix B kinds have their own templates (graph output values or image within tolerance, modifier stack re-evaluation, constraint transform and influence, effect rendering, area type). Group rows say that every member behaves as in Blender 5.3 and is covered by common tests.

Measured on the 150-row sample and a fresh 90-row sample: no statement is label-only after the change; the generic fallback class (`other`) covers 183 of 2,341 individual operator rows (8%), where the statement still names the area, the same-input comparison and undo. Remaining weakness: the template cannot know operator-specific parameters, so acceptance tests (not statements) must carry them. Class misfits seen in the fresh sample: `Trim Box Gesture` (fixed), `Face Select Hide`, `Retime Strips`, `Refresh Archive` (about 4 of 70 operator rows, class text still true but loose).

## 4. Alias and group rows, completeness

Independent check (a separate parser written for the review, not the generator's): the appendix text has 78 modules and 2,552 operators and every module heading count equals its printed count. All 2,552 `(module, operator)` pairs are in `MAPPING.csv`; no mapping line is extra or dangling; for every individual row `source.ref` equals `bpy.ops.<module>.<name>`; there are no duplicate refs. Appendix B: 3,170 mapping lines = 2,552 + 618 printed items.

Group rows: 17 (10 UI modules and 7 `wm` classes). Each lists all of its members in `notes` (checked per member, and now checked on every generator run by `check_invariants`). Defect found: the screen and console groups swallowed 11 operators that are real user outcomes (animation play, pause, step, cancel, frame, keyframe, marker and time jumps; console execute and autocomplete). They are now individual rows (Best: animation, scripting API). Left in groups on purpose: `ui.eyedropper_*` and driver copy buttons, `wm.context_*`, `wm.call_*`, window, search, preset and tool-selection operators, and file or screenshot housekeeping.

Alias rows: 6 modifier names are printed twice in Appendix B (Armature, Build, Anchor, Cache, Shrinkwrap, Smooth). They are kept as alias rows so the unique count is 77 as the plan states. The second print is very likely a distinct class that shares the label (the Grease Pencil or Mesh Sequence Cache variant), so the alias row notes now say to decide this when binding to `bpy.types`; if they are distinct, they must become primary rows before the freeze on 30 Nov, which moves the register to 2,993 rows.

## 5. Determinism and validation

`python3 parity/tools/gen_blender_register.py --check` regenerates twice into a temporary directory and compares every output file with the committed copy: OK. The run validates every row against `parity/schema/row.schema.json` (0 errors) and, new in this review, checks: unique statements, Best rows have a superiority text and non-Best rows have none, no forbidden term, every mapping line points to a row, every row has a mapping line, every group row lists each of its members, and every alias target exists. Reconciliation identities in `RECONCILE.md` all PASS and it now has a Best/Strong and factory table per file.
