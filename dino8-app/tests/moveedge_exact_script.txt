# MovePartsCommand moved every picked edge with the approximate MoveBrepEdges. For ONE edge it now calls kernel::MoveEdgeConvexPlanar first
# (both endpoints move, every incident face is re-planed through its moved corners, the others are re-trimmed, the solid stays closed) and
# falls back to the approximate move only when the kernel declines, printing the kernel's reason. Expected values are closed forms of a
# 10 x 10 x 10 cube whose top-front edge (y = 0, z = 10) is moved:
#   up by d along z : the top plane tilts through the back top edge, z = 10 + d (1 - y / 10) :  V = 1000 + 50 d,  S = 500 + 20 d + 10 sqrt(100 + d^2)
#        d = +3 : V = 1150, S = 664.403 ;  d = -3 : V = 850, S = 544.403
#   slid by s along +y within the top plane : the front wall tilts, V = 1000 - 50 s,  S = 100 + 100 + 10 (10 - s) + 10 sqrt(100 + s^2) + 2 x 10 (10 + (10 - s)) / 2
#        s = 2 : V = 900, S = 561.980
#   the vertical edge (0, 0, *) slid by 2 along +y : the cross-section (0,0),(10,0),(10,10),(0,10) loses the triangle (0,0),(0,2),(10,0):
#        V = 900, S = 90 + 90 + 100 + 100 + 80 + 10 sqrt(104) = 561.980
#   the vertical edge (10, 10, *) slid by -3 along x : the cross-section becomes (0,0),(10,0),(7,10),(0,10), area 85 :
#        V = 850, S = 85 + 85 + 100 + 70 + 100 + 10 sqrt(109) = 544.403
#   Every exact result is also checked with the app's Check (valid B-rep). The old approximate route gets the same volume and area on these
#   planar cubes but its B-rep is INVALID (brep.m_E[0] edge is not valid).
#   slid by 2 along +x : the x = 0 face would stop being planar (one corner leaves its plane): the kernel declines and says so
#   a cylinder's circular rim edge : the wall is not planar, the kernel declines
