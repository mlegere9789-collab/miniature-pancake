# --- CurveThroughSrfControlPt / ExtractPt (N x N control grid): regression
# for a dangling Document::objects_ pointer, the same bug class as
# CutVolume's own fix (see cmd_solidtools.cpp). Both
# BuildCurveThroughSrfControlPt and ExtractPt (cmd_curves2.cpp) captured
# their source object as a raw SceneObject*, then re-dereferenced that same
# pointer (o->layer_index) once per row/column or once per point, after
# ctx.Doc().Add() had already run earlier in that same loop. Add() can
# reallocate Document::objects_, so once one of the many Add() calls below
# grows past current capacity, `o` dangles for every row/column/point after
# that - and the very next one's own allocations (its curve, its user_text
# map) are likely to reuse the freed SceneObject slot, so the stale read
# lands on already-overwritten memory rather than surviving by luck. Run
# first, against a still-empty document (Document::objects_ starts at
# capacity 0, so the very first Add() below already has to grow it) so
# there's no leftover capacity headroom from later in the script that could
# mask it - a 10x10 control grid (20 Add() calls for the curve case, 100
# for the point case) is far more than enough.
