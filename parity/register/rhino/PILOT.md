# Rowpilot: 100 Rhino rows linked to existing named tests

Wave 0 job `rowpilot` (branch `w0-rowpilot`). For each row below, `acceptance[0].test_id` now names an EXISTING test (a kernel test name as registered by `RunTest(...)` in `dino8-kernel/tests/test_basic.cpp`, or `extra::<Name>` for `D8_EXTRA_TEST` in `dino8-kernel/tests/extra/`) and `notes` carries `covered by <file:line>; closed-form/oracle: <what>`.

Nothing here is credit. `status` stays `open`, `tier_now` is unchanged and `evidence` is `null`. A row counts only when a passing CI run is read by `parity/tools/percent.py` (a later step on the cand3 full CI evidence). Because `test_id` is part of the sealed spec (`regio.spec_sha`), the seal is computed when CI first credits the row.

## Method and strictness

* Each test body was read, not just its name. A row is linked only when the test checks the row's outcome against a real oracle: a closed form (volume, area, length, Pappus, Green integral, exact vertex position), an independent reference (the original curve or surface before the edit, finite differences of the source surfaces, the target surface's own derivatives, openNURBS predicates) or an exact count (Euler characteristic, Catmull-Clark counts, edge classes).
* Tests whose only checks are refusal paths (throws on bad input), round trips of stored data, classification predicates, or topology validity without a value were rejected.
* Where a test covers only part of the row (for example one object type of several), the note says so (`covers ... only`). Reviewers should weigh those rows as partial.
* Link logic: `test_id` is the bare registered test name, which is what `percent.py` matches (`kernel/<name>` also works for disambiguation). All 100 names were checked to be registered exactly once and not commented out.

## Tolerance gaps to settle before crediting

The rows keep their declared tolerance (for example SOLID rows declare `volume_rel <= 1e-6`). Several linked tests use a looser bound on a tessellated volume. They have a real closed-form oracle but a weaker bound than the row text; the review role should either tighten the test or restate the row tolerance before `verified`:

SOLID-0006 (2%), SOLID-0015 (1%), SOLID-0020 (1%), SOLID-0022 (1%), SOLID-0025 (0.3%), SURF-0023 (0.3%), SURF-0072 (1% to 2%), SURF-0078 (0.3% to 0.5%), SURF-0138 (0.3%), XFORM-0010 (1%), SOLID-0029 (1e-3 on the sphere), ANALYZE-0002 (1e-4 on sphere and torus), CURVE-0088 (1e-3 on length), SURF-0042 (no numeric oracle, see its row).
