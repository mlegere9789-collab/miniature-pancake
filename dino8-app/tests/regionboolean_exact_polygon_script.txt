# CurveBoolean's own Operation option can't be set via a trailing
# "Operation=Intersection" token on the SAME line as a preselected
# invocation ("SelID 1/2/3" then "CurveBoolean Operation=..."): with
# objects already selected, CommandEngine::AfterCallback's own
# preselection check (CommandEngine.cpp) hands them to the command and
# finishes it immediately, before CurveBoolean's own queued option token
# is ever drained - a real, pre-existing engine quirk (CurveBoolean's
# Tool has exactly one step, Objects, so there is nothing left to do once
# objects arrive), found while writing this test, not assumed. Starting
# the command with NOTHING selected instead avoids it: the option is
# drained and applied while the command is still waiting for objects
# (CurveBoolean's own Tool has no preselection left to consume at that
# point), then SelID/Enter - the same "nested selection command, then
# Enter to submit" sequence this file's own CageEdit/SelControls section
