# History / UpdateHistory extended to Sweep1 (Sweep1Command, cmd_surface.cpp;
# RebuildSweep1, history_rebuild.h), single-cross-section case only: the same
# source-curve-moves -> UpdateHistory-rederives loop history_script.txt and
# history_pipe_script.txt already prove for Extrude/Revolve/Loft/SubDLoft/
# Pipe, now for Sweep1 as a seventh tracked command - see cmd_history.cpp's
# own header comment for the full scope list. The money check is a real
# bounding-box move, not just an object count, so a fake/no-op rebuild would
# fail this the same way it would in history_script.txt/history_pipe_script.txt.
#
# The section curve (not the rail) is the one moved here. RebuildSweep1
# anchors the section where it sits along the rail (the swept surface covers
# the rail and passes through the section wherever it is - see the block
# comment above AnchoredSweep1 in cmd_surface.cpp), so the two edits below
# test two different things: sliding the section ALONG the rail (+5 in Z) must
# leave the surface covering the rail's own z=0..10 extent (it used to shift
# the whole tube to z=5..15, because the kernel's Brep::Sweep1 carries the
# section rigidly from the rail START - that was the defect); moving it
# SIDEWAYS (+3 in X) is then the edit that proves UpdateHistory genuinely
# re-derives the geometry, since it changes the swept bounding box in X.
#
# Object ids below are the deterministic 1-based counter Document::Add
# assigns, in creation order.
