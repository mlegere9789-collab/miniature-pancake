**Method** (as specified for this audit): a Python script parses every `Reg(e, "Name", factory[, CommandStatus::X[, "note"]])` call with balanced-parenthesis extraction, walking the `cmd_*.cpp` files in the exact order `Application::RegisterCommands()` calls their `Register*Commands()` functions (last registration for a given name wins, matching `CommandEngine::Register`'s `ToLower(name)` keying). Re-running it against the current tree gives:

```
COUNTS: {'Implemented': 1018, 'Partial': 24, 'Planned': 0, 'Missing': 13}
```

The 13 "Missing" are **all false positives** of the regex scan — every one is registered through a runtime loop the regex doesn't follow, confirmed by grepping each literal name:
- `cmd_state.cpp:822`: `for (const char* n : {"CheckInLicense", "CheckOutLicense", "Login", "Logout", "Libraries", "DownloadLibraryTextures"}) Reg(e, n, Say(kFree));` — accounts for `CheckInLicense`, `CheckOutLicense`, `Login`, `Logout`, `Libraries`.
- `cmd_meshtools.cpp:2209` and neighbouring lines: a table of `{extract-name, sel-name, metric, default, lambda}` entries drives `Reg(e, extract_name, ...)` / `Reg(e, sel_name, ...)` in a loop — accounts for `ExtractMeshFacesByArea/AspectRatio/DraftAngle/EdgeLength` and `SelMeshFacesByArea/AspectRatio/DraftAngle/EdgeLength`.

## 4. "Before you install" verdict

### 4.1 What works well (and is tested)
- **Near-complete Rhino 8 catalogue coverage**: 1031 of 1055 command names (97.7 %) are genuinely implemented, 24 honestly Partial for reasons that need physical hardware, an OS clipboard API, or kernel capabilities this codebase does not have, and 0 are placeholder-only.
- **Real edge fillets/chamfers/blends** on B-reps, verified to match analytic volumes.
- **A real signed-distance-field ShrinkWrap**, verified to preserve concavity rather than convex-hulling.
- **A real CPU path tracer** with a 48-material library, exercised end-to-end in CI.
- **GD&T, tables, BoM, multi-leaders, and a 33-pattern hatch library**, though none of it is a live/associative entity.
- **Real IGES and STEP import/export.**
- **SpaceMouse/3Dconnexion support** across Linux/Windows/macOS with a testable simulated protocol.
- **Real parametric 2D sketch constraints** (14 types, Levenberg-Marquardt solver) and **parametric architectural components** (Wall/Door/Window/Slab/Roof/Stair/Column/Beam with real cut openings) — both value-adds beyond the Rhino 8 catalogue.
- **A Grasshopper-class visual node editor ("Dino Flow") and a real, documented plug-in C ABI.**
- **Real sub-object (vertex/edge/face) selection and editing** — the single largest interaction gap identified in the previous audit is now closed at the data-model level.
- **Two previously-missing object snaps (Knot, Project) and a real SmartTrack** now exist.
- **CI is green on four platforms** — Linux, Windows, Windows-on-ARM, and macOS — with no unresolved merge conflicts, unlike the prior audit's mid-cherry-pick state.
- **Free, offline, honest**: the app prints exactly how a Partial command deviates, and there is no licence/account/telemetry code (§4.4).

### 4.2 What is still approximate or absent (read the note before relying on it)
- **Annotations, dimensions, tables, GD&T, and BoM are all baked curve/text geometry, not live objects** — none of it re-associates or updates when the measured geometry changes. This is unchanged from the prior audit and is the single biggest remaining gap in the 2D-drafting story despite the large amount of new *content* (GD&T symbols, tables, hatch patterns).
- **No construction history anywhere** — `History`/`RecordHistory` are still honestly Partial print-only stubs; undo is still full-document snapshots, not incremental.
- **Booleans on NURBS solids still return meshes** (via Manifold), even though edge fillets/chamfers on existing B-rep faces are now exact.
- **`ToNURBS`/`MakeSubDFriendly`** are approximate rebuilds, not exact Catmull-Clark conversion.
- **Autocomplete is prefix-only**, not the fuzzy palette doc4 promised.
- **No document tabs/MDI**, and no large-document performance testing exists.
- **The installer is unsigned** — no `signtool`/`codesign` invocation found in `packaging/`.
- **The path tracer is CPU-only**, not the GPU renderer doc4 described.
- **The 52 remaining Partial commands** (§0.1, count corrected 2026-09-09 from a live registry re-scan) are mostly genuinely blocked on hardware, OS APIs, or kernel/data-model capabilities this project does not have, plus a handful of honestly-scoped-down feature extensions (see §0.1) — not oversights, but still real gaps for a user who needs exactly one of them.

### 4.3 What is absent
A DinoCommon .NET SDK (this is a C++17 codebase — very unlikely to ever exist without a rewrite); Python/C#/RhinoScript compatibility for Dino Flow/plug-ins (the plug-in ABI is a from-scratch C ABI, not Rhino-compatible); SAT/Parasolid/SKP/FBX/glTF and most other exchange formats beyond .3dm/OBJ/STL/PLY/DXF/DWG/SVG/PDF/IGES/STEP (DWG was added since the prior pass, via the linked GPLv3 GNU LibreDWG library — see `docs/INTEROP_LIMITATIONS.md` and `THIRD_PARTY_LICENSES.md`; its entity coverage is a subset of DXF's); code signing; document tabs/MDI; live/associative annotation objects; construction history; incremental (O(change)) undo; a fuzzy command palette; multi-sheet printing with a print dialog; a UV-editing window; an OS clipboard image API; a per-version DWG/DXF "scheme" picker.

### 4.4 Hard-constraint check: no licensing, subscription, payment, or telemetry code
`grep -rniE "subscription|licen[sc]e key|payment|telemetr[iy]" src` finds only free-software statements, no functional code:
- `src/ui/Panels.cpp:539`: *"Dino 8 is free software. There are no licences, subscriptions, sign-ins or update nags to manage."*
- `src/ui/Panels.cpp:667`: *"A free NURBS, SubD and mesh modeler with Rhino 8's command vocabulary. Totally free: no subscription, no payment, no licence keys, no accounts, no telemetry."*
- `src/app/Application.cpp:707`: *"Dino 8 is free software. No accounts, licenses or subscriptions, ever."*
- `src/commands/cmd_analyze.cpp:388`: version-line text, *"Dino 8 ... - free, no subscription"*.
- `src/commands/cmd_state.cpp:821`, `:822`: the loop registering `CheckInLicense`/`CheckOutLicense`/`Login`/`Logout`/`Libraries`/`DownloadLibraryTextures` all to print the same `kFree` message.

No sockets, HTTP client, analytics library, update checker, or account UI were found in this pass beyond what the prior audit already documented (system-browser launches for `OpenURL`/`WebBrowser`/`TechSupport`/`LearnRhino`/`WhatsNew`, which make no request themselves). **Verdict: constraint satisfied.**

### 4.5 Build/test state at audit time
Clean checkout, no conflict markers anywhere in `src/` (`grep -rl "<<<<<<< " src/` returns nothing), HEAD `03a0b7b`. CI green on all 4 platform targets plus the `ctest` job. This is a materially better state than the prior audit's mid-cherry-pick, 4-failing-check snapshot.

**Update (2026-09-09):** a later pass fixed a recurring Linux CI flake unrelated to this repo's own code (a preinstalled Google Chrome apt source on the GitHub Actions runner image failing `Hash Sum mismatch` on `apt-get update`) by finding the offending apt source file by content instead of a guessed path (`.github/workflows/dino8-app.yml`). ## 5. Top gaps to close next (prioritised)

Given the current state — 1031/24/0 catalogue coverage and the specific remaining pain points from §3 — the highest-value remaining work is:

1. **Live/associative annotation objects** (dimensions, tables, GD&T, BoM, leaders, hatch) that re-associate and re-scale with the geometry they measure, instead of baked curve/text outlines — this is now the single biggest gap in the 2D-drafting story, since the *content* (GD&T symbols, tables, 33-pattern hatch library) is real but none of it updates.
2. **Construction history / associativity**, and replacing full-document snapshot undo with per-change deltas — both explicitly still absent (`Document.h:2-7`, `cmd_misc.cpp:353-355`) and the root cause of the still-unaddressed large-document-performance pain point (#4 in §3).
3. **B-rep-preserving booleans** (keep NURBS output; fall back to Manifold meshes only on failure) — edge fillets are now exact, but booleans still destroy NURBS-ness by routing through a mesh representation.
4. **PushPull** — still entirely absent from both the catalogue and the code; a top-3 review "pro" for Rhino 8 and the most SketchUp-simple workflow reviewers praise.
5. **Surface-level Class-A continuity** (true G2 `BlendSrf`, multi-edge corner fillets, CV-count control) — curve blending now has a real G2 quintic-Hermite option, but the equivalent surface operations are still an approximate tangent-magnitude boost, not a true solve.
6. **A fuzzy command palette** — autocomplete is still `WithPrefix`-only; doc4's promise and a common modern-CAD UX expectation.
7. **Code signing** for the Windows/macOS installers — still entirely unsigned.
8. **Document tabs / MDI** — unchanged, still single-document-per-process.
9. **A UV-editing window** and **a per-version DWG/DXF "scheme" picker** — two of the remaining Partial commands (`UVEditor`, `AcadSchemes`) that could become real with dedicated feature work, unlike the hardware- or clipboard-blocked ones. (`AcadSchemes` itself is Partial only because there is no such per-release-version picker UI — DWG/DXF export/import themselves are real, see §4.2's File I/O row.)
10. **A large-document performance benchmark** in `tests/` — there is currently no way to know whether the snapshot-undo/immediate-mode-UI architecture holds up at scale, which is exactly the audit's #4 pain point.
11. **Exact Catmull-Clark SubD→NURBS conversion** (`ToNURBS`/`MakeSubDFriendly`) — still an approximate rebuild through sampled points.
12. **Multi-sheet printing with a print dialog** (page setup, line-weight/colour table, all layouts → one PDF).
13. **Real `.rui`-format toolbar import/export** and a broader hand-drawn icon set — not independently re-verified as fully closed this pass.
14. **Grasshopper-format interop** for Dino Flow, if cross-compatibility with the Rhino ecosystem is ever a goal — currently a from-scratch, non-interoperable design.
